01 · Vision

Product principles

Vesha’s shift is cultural as much as technical: from “digital closet software” to “the app you open when you don’t know what to wear.”

Current identity

Digital wardrobe / DBMS — store, tag, browse, filter, and manage clothing assets.

Target identity

Habit-forming AI fashion assistant — decide, style, inspire, and get more value from clothes already owned.

Three questions, three homes

Today

What should I wear today?

Daily habit. Default landing. Weather + calendar aware. Avatar + alternatives.

Closet

What do I own?

Visual wardrobe. Image-first grid. Smart search. Pairings. Vibe Match entry.

Discovery

What could I wear?

Inspiration, AI looks, occasions, trends, social, Like → Vibe Match.

Design principles for every phase

  1. Wear > organize. Primary CTAs should be Wear / Create Look / Vibe Match—not Edit fields.
  2. One composition, low clutter. Prefer image + one decision over dashboards of chips.
  3. AI proposes, human confirms. Especially for tagging and vibe interpretation.
  4. Own wardrobe first. Recommendations prioritize what the user already owns before shopping.
  5. Language with vibe. Prefer moodful verbs (“Not feeling it”, “Switch the vibe”) over clinical labels.
  6. Learning loop. Wear / skip / reject / like must feed future ranking.

Keep & extend

  • AI identify / confirm tagging
  • Wear history as learning signal
  • Weather-aware scoring (if present)
  • Outfit entities (as compositions, not a primary tab)

Rethink / retire

  • Category tabs as primary Closet IA
  • Add as its own bottom tab
  • Outfits / Insights / Profile as peer tabs
  • Clinical “Try another” language
  • Manual multi-item wear entry after choosing a look

P1

Navigation & Closet redesign

Goal: make Vesha feel like an assistant shell, not a DBMS toolbar

User value

Opening the app feels focused. Closet looks like a real closet wall of clothes. Adding is part of Closet, not a separate “module.”

In scope

  • Replace bottom navigation with Today · Closet · Discovery
  • Default route = Today (even if Today is a lightweight shell in P1)
  • Rename Wardrobe → Closet
  • Remove Tops/Bottoms/… category tabs as primary navigation
  • Top-level filters only: Clothing · Footwear · Accessories (+ All)
  • Image-first grid: full garment visible without opening detail
  • Move Add into Closet as persistent +
  • Relocate Profile/settings to account entry (header or Closet overflow)
  • Discovery tab exists as a branded empty/coming-soon with clear promise

Out of scope

  • Full stylist redesign (Phase 2)
  • Intent search / Vibe Match / Avatar
  • Social Discovery content

Closet grid UX rules

Do

  • Large tiles, soft background, garment fills frame
  • Minimal text overlays (optional tiny category pip)
  • Tap → item detail

Don’t

  • Dense metadata rows in the grid
  • Force category tab hopping to find items
  • Require 2 navigations to see the full photo

Acceptance criteria

  • Only 3 primary tabs visible on iOS, Android, and web
  • Cold start lands on Today
  • Closet shows mixed items in one scrollable grid with 3 broad filters
  • User can add an item without leaving Closet IA
  • No broken deep links from old tab routes (redirects in place)

P2

Today — habit core

Goal: the morning screen that forms the habit

Screen composition (first viewport)

  1. Context strip — date · weather summary · (later) calendar cue
  2. Primary recommendation — title + short “why”
  3. Pieces row — clothing + footwear + accessories used
  4. Avatar panel — placeholder in P2 if Avatar not ready; wire real avatar in P5
  5. Primary CTA — Wear This
  6. Secondary CTA — moodful reject (see copy)
  7. Two alternates — always shown by default under the fold or as compact cards

Recommendation inputs

SignalBehavior
WeatherTemperature band, rain, humidity influence layering, fabric, footwear
Calendar (P2b)Infer formality from events (client meeting → formal; dinner → smart casual)
Wear historyPenalize very recent repeats; boost neglected pieces
Preferences / vibeCasual, Clean, Trendy, Bold, Minimal, Relaxed, Formal (expand over time)
OwnershipOnly items in Closet (no shopping links in Today MVP)

Reject / regenerate copy (Gen Z / mood)

Pick one primary label; keep others as A/B candidates:

  • Primary recommendation: “Not feeling it”
  • Alternates: “Switch the vibe” · “Wrong mood” · “Main character swap”

Action: regenerate primary + 2 alternates without opening a builder. Log a reject signal with previous outfit id.

Wear This behavior

  • Writes a wear-history entry for the full outfit (all item ids) in one tap
  • No manual per-item logging
  • Confirms with lightweight feedback (“Logged for today”) and refreshes context
Figure 5 — Today layout: one primary decision + two alternatives

Acceptance criteria

  • Today shows a complete recommendation without requiring the user to tap “Suggest” as a gate (auto-generate on load, with refresh control)
  • Two alternatives always present when closet can support them
  • “Not feeling it” replaces the primary set and records reject
  • Wear This creates history for all pieces in the look
  • Weather influences results (verified with hot/rainy fixtures)

P2b

Calendar-aware dressing

Optional enhancement immediately after Today core

Behavior

  • Request calendar permission with clear value prop (“Dress for today’s meetings”)
  • Read today’s events (title, time, optionally location)—not full history
  • Map events → dress context tags: Formal, Business, Smart casual, Party, Athletic, Travel
  • Surface one human cue: “Client meeting at 2pm → keeping it polished”
  • If permission denied, Today still works with weather + prefs only

Example mapping (v1 heuristics)

Event cueInferred context
interview, client, board, pitchFormal / Business
dinner, date, anniversarySmart casual / Evening
wedding, reception, puja, festivalOccasion / Festive
gym, run, yogaAthletic (or exclude from fashion primary)
flight, travel dayTravel comfort + polished layers

Acceptance criteria

  • With sample calendar fixtures, meeting language appears in “why”
  • Denial path never blocks recommendations
  • No raw calendar event contents uploaded beyond what’s needed for inference (privacy review)

Phase 2 engineering notes

  • Treat outfits as compositions of Closet item ids
  • Store recommendation sessions: proposed, worn, rejected, skipped
  • Avatar slot should be a stable component API even if it renders a mosaic fallback initially

P3

Closet intelligence

Goal: Closet answers ownership questions and creates looks, not just stores SKUs

Search modes

ModeExampleReturns
Specific“white t-shirt”Matching individual items
Intent / occasion“what can I wear to a wedding?”Suitable individual pieces (not full outfits)
Combination“what goes with my black jeans?”Compatible items from Closet

Note: complete outfits for occasions belong in Discovery / Today—not Closet search results.

Filters (UI simple, taxonomy rich)

Clothing

Shirt, T-shirt, pants, jeans, dress, skirt, suit, jacket, kurta, saree, …

Footwear

Shoes, sandals, sneakers, boots, loafers, Crocs, …

Accessories

Jewelry (earrings, rings…), watches, bags, belts, hats, …

Item detail must include

  • Full image + editable attributes
  • Last worn + wear count
  • Goes well with — pairings from user’s Closet
  • Create Look — jump into composition with this item pinned

Add clothing (inside Closet)

Ideal path: Photo → AI identifies → Confirm → Added → “Here are 3 ways to wear it.”
  • Sources: camera, library, selfie/worn photo (isolate garment when possible)
  • Multi-image session supported
  • Minimal manual fields; AI draft + quick correct
  • Optional background cleanup / crop
  • Immediate Possible Pairings after save

Acceptance criteria

  • Occasion query returns relevant pieces without fabricating outfits
  • Combination query excludes the seed item and ranks compatible categories
  • After adding a white shirt (fixture), user sees ≥1 pairing suggestion without navigating away
  • Subcategory filters work without returning to old Tops/Bottoms tab IA

P4

Vibe Match MVP

Goal: turn “I saw this vibe” into “I can wear my version tonight”

User journey

  1. User uploads an inspiration image (street style, influencer, friend, Pinterest)
  2. Vesha extracts vibe labels + structural elements (e.g., oversized top, relaxed denim, cap, sneakers)
  3. System matches Closet inventory
  4. If exact pieces exist → propose recreation
  5. If gaps exist → propose silhouette hacks (“oversized shirt ≈ baggy tee”) — never dead-end on “you don’t own X”
  6. Show: Inspiration · Your version · Avatar preview
  7. Actions: Wear This · Save Look · Switch the vibe
Figure 6 — Vibe Match pipeline

Entry points

  • Closet → “Vibe Match”
  • Discovery → after Like / Save on an inspiration

Acceptance criteria

  • Fixture inspiration with baggy tee + jeans + cap returns a closet-based proposal
  • When baggy tee missing, substitution copy proposes an oversized alternative—not a hard failure
  • Output always lists mapped elements and confidence/gaps
  • User can Wear or Save the adapted look

P5

Avatar try-on

Goal: users see the outfit as a whole on “them,” not only as a mosaic of SKUs

Why this phase is later

Avatar quality can distract from habit mechanics if introduced too early. Ship Today + Vibe Match with mosaic/fallback first; then replace the same slots with true try-on.

In scope

  • Avatar creation / upload / body basics (reuse profile height etc. where useful)
  • Layer garments (top/bottom/dress/shoes/accessories) onto avatar
  • Surfaces: Today primary, alternates thumbnail, Vibe Match result, Closet Create Look
  • Graceful fallback if a garment lacks a clean cutout

Out of scope (initially)

  • Photoreal virtual try-on indistinguishable from real photos
  • Fabric physics simulation
  • AR camera try-on

Acceptance criteria

  • Today primary recommendation renders on avatar for ≥80% of demo closet outfits
  • Missing layer does not crash—shows partial avatar + piece strip
  • Same avatar component used in Vibe Match output

Phase 5 dependency map

Must already exist

  • Stable outfit composition model
  • Clean item images (Phase 3 cleanup helps)
  • Today & Vibe Match UI slots

Unlocks next

  • Discovery previews feel tangible
  • Social shares of “your version”
  • Higher trust in AI suggestions

P6

Discovery

Goal: “What could I wear?” — inspiration without becoming a generic social network

Modules

ModuleBehavior
For YouPersonalized looks from closet + preference/wear signals
AI-generated looksComplete outfits using only owned items
Occasion discoveryDate night, birthday, wedding, office, vacation, festival, brunch, …
TrendingEditorial collections (Fall, Diwali, summer, etc.)
Like / SavePersonalization signals + saved board
Vibe Match CTAAfter Like/Save: recreate with Closet + avatar
NL discovery“casual date-night outfits”, “South Indian wedding ideas”

Product boundary

Discovery is fashion utility first. Social content must always offer a path back to the user’s closet (Wear / Vibe Match / Save look)—not endless scrolling for its own sake.

Acceptance criteria

  • For You returns looks composed from the signed-in user’s items
  • Occasion collection opens filtered inspiration + closet-feasible variants
  • Like persists and increases probability of similar vibes on Today/Discovery
  • Vibe Match from a liked card opens Phase 4 flow with prefilled inspiration

P7

Social inspiration & group matching

Later-stage network effects — after solo habit is proven

User inspiration feed

  • Users/creators post looks (still tied to garments / vibes)
  • Viewers can Like → Vibe Match using their own Closet
  • Moderation, reporting, and privacy controls required before broad launch

Group outfit matching (backlog idea → Phase 7 epic)

Examples: family wedding, friends’ holiday, couple coordinated looks.

  • Create a group event with dress code / vibe
  • Members share relevant Closet subsets or preference profiles (privacy-scoped)
  • System proposes coordinated palettes / formality alignment without forcing identical outfits
  • Each member gets a personal Wear This that fits the group story

Image search (Discovery stretch)

Upload inspiration → find similar Discovery looks and Closet Vibe Match in one pipe.

Launch gate: do not invest heavily in Phase 7 until Today weekly active habit metrics (opens → Wear This) are healthy. Social without habit becomes content debt.

13 · Systems

Cross-cutting architecture notes

Suggested domain objects

EntityPurpose
ItemGarment/footwear/accessory with taxonomy + attributes + images
Outfit / LookOrdered set of item ids + occasion/vibe metadata
WearEventTimestamped wear of outfit or item; source = today|vibe|manual
RecommendationSessionProposed looks, chosen/rejected, context snapshot
VibeAnalysisLabels, structural elements, source image ref
Inspiration / PostDiscovery content unit (editorial or user)
ReactionLike, save, wear, reject
AvatarProfileUser visual baseline for try-on
CalendarContextDerived dress codes for a day (not raw calendar dump)

AI capability map

Already foundational

  • Garment identify / attribute extraction
  • Rule or model-based outfit scoring

Net-new to plan

  • Intent search embeddings
  • Vibe & silhouette analysis
  • Substitution / hack generator
  • Avatar compositing pipeline
  • Occasion collections ranking

Taxonomy principle

UI shows 3 buckets. Backend stores fine-grained subtypes (shirt vs kurta vs saree). Recommendations and search query the fine grain; filters expose progressive disclosure.

Privacy & trust

  • Calendar: minimize scopes; store derived dress codes, not full event notes
  • Photos: clear retention; on-device crop when possible
  • Social: default private closet; sharing is explicit

14 · Measurement & decisions

Success metrics, risks, open questions

North-star metric

Wear Rate: % of Days-with-App-Open that end in a Wear This (or equivalent confirmed wear).

Supporting metrics by phase

PhaseWatch
1Tab distribution; Closet session depth; Add completion rate
2Today open → Wear This; reject rate; time-to-first-wear
3Search success; pairing CTR; post-add pairing engagement
4Vibe Match completion; substitution accept rate
5Avatar render success; influence on Wear This conversion
6Like→Vibe Match funnel; Discovery weekly reach
7Creator supply; group event completion (careful quality bar)

Key risks

  • Empty Closet cold start — Today fails without items; keep first-run checklist + fast add
  • Avatar overpromise — ship fallback mosaics; don’t block habit on try-on fidelity
  • Search confusion — Closet returns pieces; Discovery returns looks—label results clearly
  • Social distraction — delay until Wear Rate is strong
  • Taxonomy sprawl — lock a v1 subtype list before filter UI expands

Open decisions (resolve before build spikes)

  1. Final reject CTA string for v1 (“Not feeling it” vs “Switch the vibe”)
  2. Avatar: illustrated vs photo-based baseline
  3. Calendar provider scope (device calendar vs Google/Outlook OAuth)
  4. Whether saved outfits remain a first-class object in Closet or only appear as Looks
  5. Discovery content: editorial-only at launch vs user posts

Recommended near-term build order (checklist)

  1. Ship Phase 1 navigation + Closet grid
  2. Ship Phase 2 Today habit core with weather
  3. Parallel Phase 3 search/pairings
  4. Ship Phase 4 Vibe Match MVP
  5. Upgrade visuals with Phase 5 Avatar
  6. Turn on Phase 6 Discovery modules
  7. Only then explore Phase 7 social/groups
Remember the distinction: a wardrobe database helps users store clothes. Vesha succeeds when it helps them wear clothes—today, and again tomorrow.
